# Modern Terminal Design

## 개요

이 스킬은 Agent Dock의 프로젝트 로컬 디자인 기준을 구현 지침으로 바꾼다.

피그마 파일을 전제로 삼지 않는다. 사용자가 말로 정한 취향과 프로젝트 문서의 디자인 가이드를 기준으로 삼는다.

## 먼저 확인할 문서

UI를 만들거나 수정하기 전에 다음 문서를 읽는다.

* `docs/modern-terminal-design-guide.md`
* `docs/frontend-conventions.md`
* 관련 기능 스펙

## 작업 절차

1. 현재 화면의 역할을 먼저 파악한다.
2. 화면이 agent, repo, worktree, 파일, Git 상태, 에디터, 터미널 중 어떤 맥락을 보여주는지 정리한다.
3. 기존 컴포넌트 구조와 CSS 방식을 확인한다.
4. `modern dark`의 깊이감과 `terminal`의 정보 밀도를 함께 적용한다.
5. 화면이 기능 구현처럼 보이더라도 실제 기능이 요청되지 않았으면 정적 UI 상태로 둔다.
6. 모바일과 데스크톱에서 텍스트가 넘치거나 패널이 겹치지 않는지 확인한다.

## 시각 기준

* 배경은 거의 검정에 가까운 다크 톤으로 만든다.
* 패널은 얇은 경계선, 약한 글로우, 내부 하이라이트로 층을 만든다.
* 인디고/보라 액센트는 선택 상태와 주요 행동에 사용한다.
* 터미널 그린은 실행 중, 연결됨, 정상, sync 같은 상태 신호에 사용한다.
* 경로, 로그, status code, prompt는 모노스페이스를 사용한다.
* 주요 제목은 산세리프를 사용해 modern dark의 정제된 인상을 만든다.
* CRT scanline, 커서 blink, terminal prompt 같은 효과는 약하게 사용한다.

## 레이아웃 기준

* 앱 셸은 좌측 세션/파일 맥락, 중앙 에디터, 우측 상태/작업 맥락, 하단 터미널의 구성을 우선한다.
* 페이지 섹션 전체를 큰 카드로 감싸지 않는다.
* 반복되는 세션, 파일, 상태 항목은 작은 행이나 카드로 표현한다.
* 고정 포맷 UI는 `minmax`, `aspect-ratio`, 명확한 높이 같은 안정적인 크기 제약을 둔다.
* 좁은 화면에서는 패널을 세로로 쌓고, 터미널/로그 텍스트는 줄바꿈되게 한다.

## 문구와 상태 표현

화면 문구는 제품 사용 상태처럼 작성한다.

좋은 예:

* `[OK] worktree attached`
* `~/workspace/agent-dock`
* `agent: claude-code/main`
* `terminal: session restored`
* `diff +12 -3`

## 피해야 할 방향

* 마케팅 랜딩 페이지처럼 과장된 hero만 만드는 방향
* 큰 그라디언트 덩어리나 장식용 오브 중심의 화면
* 실제 제품 맥락과 상관없는 추상 일러스트
* 터미널 감각을 초록색 텍스트만으로 처리하는 방향
* 카드 안에 카드를 계속 중첩하는 구조
* 텍스트가 버튼, 탭, 패널 안에서 잘리는 레이아웃

## 완료 전 확인

* 디자인 가이드와 구현이 일치하는지 확인한다.
* `pnpm typecheck`와 `pnpm build`를 실행한다.
* 가능한 경우 로컬 화면을 직접 열어 데스크톱과 모바일 폭에서 확인한다.
